# Статус прототипа

> **Текущий контракт, 15.10.2026:** текстовый PDF сначала проходит поддерживаемый разбор
> исходных таблиц; неподдерживаемый текст и сканы зависят от настроенного провайдера.
> Локальный OCR не является требованием релиза. Для обычной позиции итоговые КАЦ/ТКП
> требуют трёх независимых допустимых продавцов и выбирают три наибольшие цены при сохранении
> полноты поиска и проверки товара, единицы, даты и продавца. Неизвестный регион поставки —
> предупреждение; отсутствие данных не подтверждает Москву. Цены из писем и собственное
> оборудование Графтио обрабатываются отдельно; отсутствующая собственная цена не равна нулю.
> Скриншоты — вспомогательные приложения с ограниченной попыткой и предупреждением при
> недоступности, без автоматической проверки содержимого. Сводка поиска и черновик доступны
> при недоборе; это не готовые итоговые документы. Полная текущая спецификация и готовность
> к развёртыванию не приняты. Подробный текущий поток — [инструкция](INSTRUCTION.md).

## Готово и проверено (детерминированное ядро, без сети)

- **Модели данных** (`engine/models.py`) — позиции, офферы, реквизиты, строки ТСН.
- **Сборщик КАЦ** (`engine/builders/kac_xlsx.py`) — формат эталонного образца 1-в-1: 17 колонок A–Q,
  блоки по 3 строки, объединения A..J, графа H = G/1.22 (НДС 22%), графа Q = № страницы ТКП,
  гиперссылки, позиции из писем одной строкой. ✓ сверено с эталоном.
- **Сборщик Тома ТКП** (`engine/builders/tkp_pdf.py`) — обложка + страница на позицию (3 пары
  «карточка товара + реквизиты»), реквизиты продавца **текстом** (Наименование/ИНН/КПП), шапка
  «Дата фиксации», подвал «НДС 22%», кириллический шрифт. ✓ рендер.
- **Сборщик ТСН + фильтр** (`engine/builders/tsn_xlsx.py`) — расчёт «ТСН в текущих ценах»,
  %, решение, исключение позиций ТСН>КАЦ из КАЦ. ✓ проверено.
- **Сквозной демо-прогон** (`engine/demo_run.py`) — собирает все 3 файла на синтетике. ✓
- **Интерфейс** (`web/index.html`, `web/app.js`) — трёхшаговый поток: параметры+файлы →
  редактируемая таблица позиций/цен → сборка. Миниатюры скриншотов в строке оффера с зумом,
  кнопки «📷 снять скриншот» (по URL) и «🔎 найти цены» (по позиции). ✓ проверено в превью.
- **Деплой UI** — GitHub Actions → Pages (`.github/workflows/pages.yml`).
- **Движок** — FastAPI (`engine/app.py`): `/parse`, `/build`, `/capture`, `/search_position`,
  `/cache/{name}`, `/base` + `/base/refresh|add` + `DELETE /base/{key}` (база-кэш) + оркестратор
  (`engine/pipeline.py`).
- **Ручной режим без сети** — `skip_search` + ручные цены/расценки ТСН. Скриншоты, заданные/найденные
  в таблице, пробрасываются в Том ТКП. ✓ тесты `engine/test_build_manual.py`, `engine/test_endpoints.py`.

## LLM-слой (`engine/llm.py`)

- Провайдер выбирается `LLM_PROVIDER` (.env): **`deepseek`** (активен) или `anthropic`.
- DeepSeek — через OpenAI-совместимый endpoint (httpx, JSON-режим), модель `deepseek-chat`. Без vision.
- Сканы спецификаций распознаёт **локальный OCR** (`spec_pdf._ocr_backend`): Apple Vision (`ocrmac`,
  macOS) → Tesseract (Linux). Claude vision — фолбэк только при `LLM_PROVIDER=anthropic`.

## Реализовано, требует боевой проверки на масштабе

- **Парсер спецификации** (`engine/parsers/spec_pdf.py`) — PDF (PyMuPDF/OCR),
  JPG/PNG/TIFF (OCR), DOCX (python-docx), XLSX (openpyxl), диспетчер по расширению,
  структуризация LLM. Четыре реальных JPG-страницы 37–40 дали все позиции 1–93 через
  `/parse`, но OCR пропускает отдельные количества и единицы измерения; нужна сверка.
  Повторный прогон 29.09: 13 нулевых количеств, одна пустая единица. В UI можно
  исправить марку/артикул; изменение исходных полей сбрасывает отметку сверки.
  Сверку можно сохранить в JSON-черновик с исходными файлами и восстановить после
  перезагрузки страницы. Подготовлен импортируемый черновик всех 93 строк с 51
  подтверждёнными по JPG исправлениями; в том числе у позиции 77 количество `5`,
  хотя OCR вернул ненулевое `1`. Позиции 3–8, 10–21, 23–39, 41–65,
  67, 71–91 и 93 сверены целиком; 10 строк остаются
  на сверке. Причины для них показаны в интерфейсе. Если исходник не позволяет
  уточнить поле, пользователь может явно принять строку с письменным замечанием;
  перед сборкой эти позиции снова показываются в предупреждении.
- **Парсер писем** (`engine/parsers/letters.py`) — LLM.
- **Выдача** (`engine/search/search_engine.py`) — SERP-API XMLRiver (`xmlriver_search`,
  `search_on_sites` для site:-поиска по поставщикам) → Yandex API → браузерный фолбэк.
- **Поисковый агент** (`engine/search/agent.py`) — основной список `Поставщики.md`, затем при
  нехватке предложений отдельный резерв `Поставщики_резерв_Москва.md`; извлечение цены/региона/ИНН
  (DeepSeek), скриншот карточки, отсев капчи/выдуманных ИНН. `[поиск]`-логи.
- **База-кэш** (`engine/search/base_db.py`) — cache-first, матчинг точный+LLM, ручное/авто наполнение.
- **Реквизиты продавца** — `Поставщики.md` для доверенных + добор с сайта (`requisites/supplier.py`).
- **ТСН-2001** — локальный справочник (`engine/tsn/local_db.py`); `mos_ru.py` не используется.
