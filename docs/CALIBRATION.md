# Калибровка на реальных данных

> Актуально на июнь 2026. LLM = DeepSeek, сканы — локальный OCR, выдача — XMLRiver, ТСН —
> локальный справочник. Общий контекст — [`HANDOFF.md`](HANDOFF.md).

Сетевые/LLM-этапы (разбор спецификации, автопоиск цен, скриншоты) работают только на машине
сметчика — с ключами, установленным браузером и российским IP. Для пошаговой проверки есть
диагностический инструмент `engine/calibrate.py`.

## Подготовка

```bash
cd engine
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium
cp .env.example .env        # впишите DEEPSEEK_API_KEY, DADATA_TOKEN, XMLRIVER_USER + XMLRIVER_KEY
```

На Linux/VPS для распознавания сканов дополнительно нужен Tesseract
(`apt install tesseract-ocr tesseract-ocr-rus`, `pip install pytesseract`); на macOS OCR ставится
из `requirements.txt` (`ocrmac`, Apple Vision).

## Запуск диагностики (из корня репозитория)

```bash
# окружение целиком (ключи, playwright, OCR, индексы ТСН):
python -m engine.calibrate

# только разбор спецификации:
python -m engine.calibrate --spec "путь/Спецификация_АК.pdf" --discipline АК

# спецификация + письма + поиск по 2 позициям + локальный справочник ТСН:
python -m engine.calibrate \
  --spec "путь/Спецификация_ЭМ.pdf" --discipline ЭМ \
  --letter "путь/Счет.pdf" \
  --search 2 --tsn

# производители уникального оборудования (не искать онлайн):
#   в .env — CUSTOM_MAKERS=ЗаводА;ЗаводБ   либо   --unique "подстрока1; подстрока2"
```

Инструмент печатает отчёт по этапам (✓/⚠/✗). **Скопируйте вывод и пришлите** — по нему
откалибруем промпты и селекторы.

## Что проверяем на каждом этапе

1. **Окружение** — заданы ли ключи (`DEEPSEEK_API_KEY` или `ANTHROPIC_API_KEY` по
   `LLM_PROVIDER`), установлен ли браузер, доступен ли OCR, загрузились ли индексы `индексы.md`.
2. **Разбор спецификации** — тип файла (текст/скан), число и состав позиций, верно ли помечены
   уникальные (из писем).
3. **Письма** — извлечены ли цены и ИНН поставщика.
4. **Онлайн-поиск** — сколько источников найдено (цель ≥ `MIN_SOURCES`, по умолчанию 5), регион
   складов, цены, ИНН, сделаны ли скриншоты.
5. **ТСН-2001** — загрузился ли коэффициент пересчёта из `индексы.md`, нашлась ли базовая расценка
   по наименованию в `ТСН-2001_электро_автоматика.md`.

## Признаки корректного разбора спецификации

- Число основных позиций совпадает с бумажной спецификацией.
- Подпозиции «в составе» (компоненты комплекта) **свёрнуты** в родительскую позицию.
- Строки-заголовки разделов («Прочее», «Расходные материалы») в позиции **не попали**.
- Позиции с заводом-изготовителем из `CUSTOM_MAKERS` (или подходящие под `--unique`) помечены
  `[УНИК.]` — цена берётся из писем, онлайн-поиск не выполняется.

## Спецификация-скан

Скан без текстового слоя распознаётся **локальным OCR** (Apple Vision на macOS, Tesseract на
Linux) → текст → LLM-структуризация. Claude vision используется только при `LLM_PROVIDER=anthropic`
и отсутствии OCR. Проверьте, что число позиций и наименования совпадают с бумажной спецификацией;
на сканах возможны ошибки распознавания — правьте в таблице UI.

## Типичные точки калибровки

- **Поиск даёт мало источников** — расширить список запросов
  (`engine/search/agent.py:build_queries`), проверить баланс/лимиты XMLRiver, добить позиции
  вручную (кнопка 📷 по найденному URL).
- **Регион не Москва/МО** — логика в промпте `EXTRACT_SYSTEM` (`engine/search/agent.py`); в UI
  склад правится вручную, не-московские строки подсвечиваются.
- **Реквизиты по ИНН пустые** — проверьте `DADATA_TOKEN`; фолбэк — скрейп сайта продавца
  (`engine/requisites/supplier.py`); для доверенных поставщиков реквизиты берутся из
  `Поставщики.md`.
- **Расценка ТСН не находится** — уточнить наименование позиции; проверить, что нужный отдел не
  исключён из `ТСН-2001_электро_автоматика.md`; при неудаче — ручной ввод базовой расценки и
  коэффициента.
- **Капча магазина** (напр. `vseinstrumenti.ru`) — headless-заход отсекается детектором;
  нужен резидентный прокси / сохранённые cookie.
