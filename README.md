# КАЦ-генератор — конъюнктурный анализ цен

Веб-приложение для сметчика: по спецификации оборудования (РД, в т.ч. сканы) и письмам с ценами
на уникальное оборудование формирует документы и отдельную сводку поиска:

1. **Том ТКП** (PDF) — скриншоты карточек товара + панели реквизитов продавца.
2. **КАЦ** (Excel) — три наибольшие допустимые цены от независимых продавцов на обычную позицию.
3. **Сводка поиска** (Excel) — все позиции, найденные цены и ссылки на карточки, причины
   отклонения и недобора. Её можно скачать до сборки документов, даже если цены найдены не везде.

В режиме с ТСН дополнительно формируется файл ТСН-2001 (Excel) для сравнения с расценками.

## Архитектура

- **`web/`** — статический интерфейс HTML/CSS/JavaScript, который локально отдаёт FastAPI.
- **`engine/`** — локальный движок (Python + FastAPI + Playwright), запускается на машине сметчика.
  Делает тяжёлую работу: парсинг PDF/JPG/PNG/TIFF/DOCX/XLSX, поиск цен, скриншоты,
  парсинг mos.ru, сборку выходных файлов.
  Доступ к внешним источникам зависит от настроенного маршрута и ограничений самих сайтов.

UI и API доступны по `http://127.0.0.1:8765/`.
Текстовый PDF сначала разбирается по поддерживаемым исходным таблицам; если таблица не
поддерживается, текст передаётся настроенному провайдеру. Для сканов путь распознавания
зависит от провайдера; наличие Cloud.ru-адаптера не означает, что он настроен в данном окружении.
Установка локального OCR не является требованием этого релиза. Неполные исходники и поля
для сверки остаются видимыми и не считаются готовой спецификацией.

Недобор независимых допустимых продавцов блокирует итоговые документы, но не сводку поиска.
Цены уникального оборудования из писем и собственное оборудование Графтио обрабатываются
отдельно: отсутствующая цена Графтио обозначается явно, полная стоимость не определяется.
Скриншоты — вспомогательные приложения: одна ограниченная попытка съёмки, при неудаче —
предупреждение о недоступном снимке; сама по себе эта неудача не отменяет допустимую цену.
Автоматическая проверка содержимого снимка не требуется. Корректность товара, цены, единицы,
даты, продавца и исходных подтверждений сохраняется.
Неизвестный регион поставки показывается предупреждением и сам по себе не исключает цену;
явно несовместимые условия поставки остаются основанием отказа. Москва не выводится из отсутствующих данных.

Проверка сайтов поставщиков пока служит внутренней диагностикой: отчёт сохраняется в
`engine/data/output/supplier_audit.json`, а интерфейс сметчика его не показывает.
Автоматический аудит проверяет контрольные карточки и не меняет списки поставщиков.
В отчёте есть отдельный счётчик прямых поставщиков: `poisk.im` помечен как агрегатор,
`russvet.ru` — как корпоративный сайт с магазином на уже указанном `rs24.ru`.
Их страницы не принимаются за самостоятельные ценовые предложения при обычном поиске.
Для `artem-tools.ru` движок использует отдельный постоянный профиль видимого Chrome в
`engine/data/cache/browser_profiles/artem-tools/`: после ручного прохождения KillBot
проверенный профиль переиспользуется и не попадает в Git. Если сайт снова потребует
проверку, запустите `python -m engine.authorize_supplier` из корня проекта и пройдите
её в открывшемся окне Chrome. `vseinstrumenti.ru` в автоматическом браузере пока
отвечает 403 даже при доступности для человека. Повторная проверка в обычном Chrome,
Playwright и прямым HTTP-запросом через тот же прокси показала, что автоматический сбор
цен с этого сайта в текущей конфигурации ненадёжен. Источник не считается рабочим для
автоматического поиска; для него нужен согласованный B2B-прайс/API либо ручная цена.

Поиск использует единый согласованный [`Поставщики.md`](Поставщики.md): все 36 сайтов сразу, без резервной фазы. Регион поставки Москва/МО принимается по этому перечню; наличие, самовывоз, НДС и продавец карточки требуют своих доказательств. Исторический резервный файл не читается поиском. Начальный план охватывает
весь перечень, дальнейшие проверки зависят от результатов по каждому источнику; первые три
цены не заменяют выполнение назначенного плана. Произвольные сайты из общей выдачи не добавляются.

## Быстрый старт (локально)

```bash
# Из корня репозитория: подготовить окружение движка
python3 -m venv engine/.venv
engine/.venv/bin/python -m pip install -r engine/requirements.txt
engine/.venv/bin/python -m playwright install chromium
cp engine/.env.example engine/.env  # заполнить ключ выбранного LLM-провайдера

# Запустить движок вместе с интерфейсом
engine/.venv/bin/python -m uvicorn engine.app:app --host 127.0.0.1 --port 8765
```

Откройте `http://127.0.0.1:8765/`. На macOS с готовым окружением можно запустить
`start.command` из корня репозитория.

Подробности — в [`docs/INSTRUCTION.md`](docs/INSTRUCTION.md).

## Ключи и сервисы

| Переменная | Назначение | Где взять |
|---|---|---|
| `LLM_PROVIDER` и ключ выбранного провайдера | настроенный путь разбора спецификации/писем и сопоставления; поддерживаются Anthropic, DeepSeek и Cloud.ru | настройки выбранного провайдера |
| `DADATA_TOKEN` | реквизиты по ИНН (наименование/КПП/адрес) | dadata.ru (есть бесплатный тариф) |
| `XMLRIVER_USER`, `XMLRIVER_KEY` | поиск XMLriver при настроенном доступе; другие пути зависят от конфигурации | xmlriver.com |

## Статус

Основные этапы реализованы; полная текущая спецификация ещё не принята как готовый
сквозной результат, готовность к развёртыванию не подтверждена. История проверок — в
[`docs/STATUS.md`](docs/STATUS.md). **Продолжение работы / новая сессия:**
[`docs/HANDOFF.md`](docs/HANDOFF.md).

Боевая калибровка сетевых этапов (разбор PDF, поиск, mos.ru) — через диагностический CLI
`python -m engine.calibrate`; см. [`docs/CALIBRATION.md`](docs/CALIBRATION.md).
